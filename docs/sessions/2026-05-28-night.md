## Архитектура «Anti-shutdown VPN»

```
📱 Мобильный (МТС/Билайн/Мегафон)
  ↓ ClientHello SNI=api-maps.yandex.ru на 443
  ↓ DPI: whitelist → пропускает
  ↓
🇷🇺 Yandex Cloud VM ru-relay-1
  ├─ Xray Reality (in), dest=api-maps.yandex.ru:443
  ├─ Smart routing:
  │   • geoip:ru → direct (РФ IP, Сбер/Госуслуги работают)
  │   • else → outbound aeza-relay (chain к Frankfurt)
  └─ Outbound "aeza-relay" → VLESS-туннель к Aeza Frankfurt
🇩🇪 Aeza Frankfurt (текущий зарубежный exit)
  └─ выход с DE IP (YouTube/Insta работают)
```

**Ключевой инсайт:** для shutdown-bypass нужен **РФ-located** сервер
(потому что cert chain должен matches whitelist-домен, а только из РФ
yandex.ru резолвится в РФ Yandex IP). С зарубежного сервера whitelist-SNI
не сработает.

**Конкуренты:** StealthSurf делает то же — 16 РФ-VPS на инфраструктуре
Beeline B2O CDN, Yandex Cloud, Cloud.ru. Используют SNI типа
`gp.x5.ru`, `api-maps.yandex.ru`, `iv.kommersant.ru`, `www.vk.com`,
`cdp.x5.ru`. Подробности в Obsidian → `[[Claude session log]]`.

## Важные warning'и для Claude'a Олега

1. **НЕ менять SNI/dest на проде вслепую.** Обязательно сверять что
   cert chain matches:
   ```bash
   openssl s_client -connect <dest>:443 -servername <new_sni> </dev/null 2>&1 | grep -E "subject|verify"
   ```
2. **«VPN не работает в РФ» = смотреть на ПОРТ в первую очередь.** Не
   SNI, не shutdown-whitelist. 95% случаев — порт.
3. **404 от агента (`list_peers(vless): 404`) КРИТИЧНО.** В прошлый раз
   я (Sonnet) пропустил → был money leak: counters не считались →
   юзеры качали unlimited. Зафиксил Opus 28.05.
4. **Не делать SSH-ключевой setup для рф-relay без согласования.**
   Yandex Cloud по умолчанию включает OS Login — нужно либо через него,
   либо отключить и поставить обычные ключи. Этот вопрос ещё открыт.
